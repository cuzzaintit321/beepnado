How to troubleshoot HTTP 502 and 503 errors

Diagnose common gateway and service availability failures.

Why it matters

A 502 generally means a gateway received an invalid upstream response; a 503 indicates temporary service unavailability. Neither status alone proves the root cause.

How to set it up

Check the public response, reverse proxy logs and application health. Verify upstream connectivity, resource usage and recent deployments before restarting services.

What to verify

Compare the incident timestamp with deployment and maintenance records. Use BeepNado’s recorded status and timing as evidence, not a definitive diagnosis.
