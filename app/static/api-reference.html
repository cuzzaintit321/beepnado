BeepNado Management API v1

Use HTTPS and Authorization: Bearer YOUR_API_KEY. Keys are workspace-bound, expire and have specific scopes. Never embed keys in browser code. Create and revoke keys in the dashboard.

List monitors

curl -fsS -H "Authorization: Bearer $BEEPNADO_API_KEY" \
  https://app.beepnado.com/api/v1/monitors

Create a website monitor

curl -fsS -X POST \
  -H "Authorization: Bearer $BEEPNADO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"My website","url":"https://example.com","authorized":true}' \
  https://app.beepnado.com/api/v1/monitors

Only monitor targets you own or are authorized to monitor. Optional rules: required_phrase, expected_status, max_response_ms. PATCH rules changes only supplied fields. Network monitor input uses name, kind, target, authorized and kind-specific options.

Pagination and errors

Monitor lists use after (default 0); checks and incidents use before. Set limit between 1 and 100. Follow next_after or next_before until null. HTTP 401 invalid/expired token; 403 insufficient scope or plan capacity; 404 missing or inaccessible resource; 422 invalid input; 429 rate limit (honor Retry-After). Creation is not idempotent: check existing resources before retrying after uncertain failures.

Rate limits per workspace per fixed minute: Free 30, Pro 60, Team 120, Scale 240. Active key limits: 1, 3, 10, 25 respectively. API key authentication is independent of browser login. No billing, team administration, or secret rotation endpoints are exposed.

API beta: response formats may evolve; no availability SLA.
